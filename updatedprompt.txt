# EDVENTURE – COMPLETE WHATSAPP CHATBOT & LEARNING MANAGEMENT SYSTEM

## Project Overview

Design and develop a complete, dynamic WhatsApp-based learning and assessment management platform for Edventure.

The platform will consist of two interconnected systems:

1. **Admin Panel:** A centralized dashboard where administrators manage employees, video content, learning modules, assessments, questions, answer keys, score calculations, scorecards, certificates, reminders, and reports.

2. **WhatsApp Chatbot:** An automated learning assistant through which employees register, receive learning videos, complete assessments, receive automatically generated scorecards, and progress through multiple learning modules.

The entire system must be dynamic and admin-controlled. Administrators should be able to manage the complete learning journey through the Admin Panel without requiring developers to change the chatbot code whenever a new video, assessment, question, or reminder schedule is added.

When a video is scheduled for an employee:

1. Fetch the configured video URL from the database.
2. Attempt native WhatsApp video delivery if the file format, size, URL accessibility, and WhatsApp API requirements permit it.

4. The link should open the video in the most suitable available player.

Prefer playback within WhatsApp when supported, but provide a reliable external playback fallback.

Do not assume that all Google Drive or Firebase links will play natively inside WhatsApp.

# PART 3: VIDEO COMPLETION TRACKING

## STAGE 5: VIDEO DELIVERY AND COMPLETION

After successful registration and consent, the chatbot welcomes the employee.

Message:

"Welcome to Edventure! Let's begin your learning journey. Here's your first video for today."

The chatbot fetches Video 1 from the Admin Panel and sends it to the employee.

Record the following:

- Employee ID
- Module ID
- Video ID
- Video URL
- Video Delivery Timestamp
- Delivery Status
- Completion Status

### Video Completion Instruction

After delivering the video, send:

"Please watch the complete video and type FINISH once you have completed watching it."

### Decision: Has the Employee Sent FINISH?

**YES:**
- Update video status to Completed (Self-reported).
- Record completion timestamp.
- Cancel all pending reminders.
- Unlock the associated assessment.
- Trigger assessment delivery.

**NO:**
- Keep the video status as Pending.
- Activate the Reminder Management Engine.
- Continue checking completion status.

### Important Technical Consideration

WhatsApp does not automatically provide reliable completion tracking for externally hosted video links.

The FINISH response should be treated as self-reported completion.

If verified playback tracking is required in the future, integrate a video player or hosting platform that provides authenticated watch-progress events.

## STAGE 6: REMINDER MANAGEMENT

Create a dedicated **Reminder Management** section in the Admin Panel.

The administrator must have complete control over reminder schedules, timing, frequency, messages, and activation.

### 1. Default Reminder Schedule

Use the following as the initial default configuration:

| Reminder | Time After Video Delivery |
|---|---|
| Reminder 1 | 20 Minutes |
| Reminder 2 | 1 Hour |
| Reminder 3 | 4 Hours |
| Reminder 4 | 6 Hours |
| Reminder 5 | 24 Hours |

These are only default values. They must be editable.

### 2. Admin Customization Options

Allow administrators to:

- Enable / Disable the complete reminder system.
- Add new reminders.
- Edit reminder timings.
- Delete reminders.
- Change reminder sequence.
- Configure reminder frequency.
- Set the maximum number of reminders.
- Customize each reminder message.
- Enable / Disable individual reminders.
- Set different reminder schedules for different learning programs.
- Configure reminder schedules globally or for individual modules.
- Save reminder configurations as reusable presets.

### 3. Reminder Timing Configuration

Allow administrators to select a time unit:

- Minutes
- Hours
- Days

Example custom configuration:

| Reminder | Configured Timing |
|---|---|
| First Reminder | 30 Minutes |
| Second Reminder | 2 Hours |
| Third Reminder | 5 Hours |
| Fourth Reminder | 12 Hours |
| Fifth Reminder | 24 Hours |

The administrator should also be able to add more reminder intervals.

### 4. Reminder Execution Logic

When a video is delivered:

1. Record the original delivery timestamp.
2. Fetch the active reminder configuration.
3. Schedule the reminders.
4. Before every reminder, check the latest video completion status.

Decision:

**Has the employee sent FINISH?**

If YES:
- Immediately cancel all remaining reminders.
- Update the video completion status.
- Record completion timestamp.
- Trigger the corresponding assessment.
- Do not send additional reminders.

If NO:
- Send the configured reminder.
- Update reminder history.
- Continue to the next scheduled reminder.

If FINISH is received between two reminders, the system must immediately stop the remaining reminder jobs.

### 5. Custom Reminder Messages

Allow administrators to customize messages.

Example:

First Reminder:

"Hi! Your Edventure learning video is still pending. Please watch the video and type FINISH once completed."

Second Reminder:

"Friendly reminder! Complete your learning video to unlock the assessment."

Final Reminder:

"Your learning activity is still incomplete. Please complete the video and type FINISH to continue your learning journey."

Support dynamic variables:

- Employee Name
- Video Title
- Module Number
- Reminder Number
- Video Link

### 6. Reminder Tracking

Display the following in the Admin Panel:

- Employee Name
- Employee ID
- Video Title
- Video Delivery Time
- Scheduled Reminder Time
- Actual Reminder Time
- Reminder Number
- Delivery Status
- Completion Status
- Next Reminder Time

Statuses:

- Scheduled
- Sent
- Delivered
- Failed
- Cancelled
- Completed

### 7. Technical Requirements

- Calculate reminders from the original video delivery timestamp.
- Use a background job scheduler or message queue.
- Check the latest completion status before every reminder.
- Prevent duplicate reminders.
- Cancel remaining reminders when FINISH is received.
- Record failed reminder attempts.
- Support configurable retry policies.
- Define whether existing scheduled reminders are updated when an admin changes the configuration.
- Respect WhatsApp's 24-hour customer service window and approved template requirements outside that window.

# PART 7: AUTOMATIC EVALUATION AND SCORING ENGINE

## STAGE 9: AUTOMATED ASSESSMENT EVALUATION

After assessment submission, the backend automatically evaluates objective questions using the answer keys configured by the administrator.

### Example

| Question | Marks | Employee Answer | Result |
|---|---:|---|---|
| Q1 | 5 | Correct | 5 |
| Q2 | 5 | Correct | 5 |
| Q3 | 10 | Incorrect | 0 |
| Q4 | 10 | Correct | 10 |

Total Marks: 30

Marks Obtained: 20

Percentage: 66.67%

### Automatic Evaluation Requirements

- Compare submitted answers against the configured answer key.
- Calculate marks obtained.
- Apply negative marking if enabled.
- Calculate percentage.
- Determine Pass / Fail.
- Store assessment results.
- Update the Admin Panel.
- Generate the scorecard.

For manual-evaluation questions:

- Mark the assessment as Pending Evaluation.
- Allow authorized admins to evaluate answers.
- Recalculate the final result after manual marks are submitted.

Correct answers and answer keys must never be exposed to employees through the chatbot or client-side assessment interface.

After completing the first module:

1. Video 1 is completed.
2. Assessment 1 is submitted.
3. Assessment 1 is evaluated.
4. Scorecard 1 is generated.
5. Module completion conditions are checked.
6. Video 2 is unlocked.

### Important Rules

- Every video must have its own associated assessment.
- Every assessment must have its own answer key.
- Every assessment must generate its own scorecard.
- Module progression must follow the admin-configured sequence.
- The admin must be able to configure whether passing is mandatory for progression.
- If an employee fails, the system should follow the configured retry or retake policy.
- The admin must be able to manually override module progression where authorized.
